Uniform artifact interfaces, 2026-10-22

Completion contract
Both SignedInvoice and SignedVoucher provide from_dict/from_json and to_dict/to_json,
plus framework-neutral json_schema. Both optional Pydantic annotations delegate to
these methods through one adapter. Protocol parsing remains authoritative; schema
projection and framework integration never authenticate or select trusted keys.
Existing segment bytes, signatures, hashes, ordered EIP-712 types and rejection
scenarios must remain intact. Base invoice imports must not acquire optional imports.

Provenance and adaptations
Copy and edit the existing 0.4.0 owners at source revision
1f4c3605baf659ed11a1eedc5b38cff41b0e6ab0. Its donor provenance is in note 010.
Move voucher.py into voucher/codec.py, retaining the public wire.voucher imports;
the package permits the matching wire.voucher.pydantic entrypoint. Replace the
invoice-specific adapter with a shared field-independent bridge. Derive invoice
schema fields and bounds from dataclass metadata; voucher schema fields and order
from the existing ordered contract definition and lexical constants. The small
object-schema helper derives required names from its properties, without becoming
a schema interpreter or participating in runtime validation.

The framework's strict dictionary boundary rejects wrong outer input types before
the core mapping parser. Malformed mapping content raises the existing protocol
ValueError family, so no catch-and-rethrow wrapper is needed for TypeError.

Evolution and limits
Changing an invoice dataclass field bound changes its schema and adapter projection.
Changing a contract field's order or lexical kind changes its schema projection;
the fixed profile still requires deliberate protocol qualification. Voucher's two
transport keys remain explicit local protocol spelling. JSON Schema describes lexical
structure, not the uint256 ceiling, low-s scalars or decoded JWS validity. Raw duplicate
members can only be rejected before framework parsing, through from_json on original
bytes or the application's containing JSON owner. No new dependencies or locks.
