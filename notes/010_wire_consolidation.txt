pay-to-play-wire consolidation — source and qualification record

Purpose and boundary

The repository is pay-to-play-wire; the Python distribution and namespace are
wire, version 0.4.0. wire.invoice owns the existing five-field Ed25519 JWS
profile. wire.voucher owns the existing fixed PayToPlay/2 EIP-712 profile.
Applications retain trust discovery, registered-position authorization,
invoice/voucher correspondence, channel policy, persistence and payment effects.
The root namespace has no eager optional imports or compatibility reexports.

Best practices retained

Make help requires no prerequisites. Acquisition with a command-line interface,
offline byte verification, image preparation, package builds, checks, release
and Pages remain explicit separate actions. The maintained checks use bounded
nonroot offline containers with immutable admitted images, read-only exact
inputs/root, dropped capabilities, no new privileges and no credential/socket
mounts. Failed native process retirement retains evidence rather than guessing
cleanup succeeded. Host orchestration owns GitHub credentials and external
publication. Release qualification captures a committed source snapshot and
verifies downloaded draft assets before publication. Pages proves the live
source revision. Published historical assets are never replaced.

Packaging checks derive runtime members from source.json, captured independently
before backend execution, compare source/wheel/rebuilt payload bytes, and install both wheels
without source mounts. Independent environments exercise base, pydantic,
voucher and both extras so prior installs cannot conceal missing closure.
Meaningful tests retain all donor rejection scenarios and add an actual
invoice-to-voucher handoff with distinct provider, deployment and signer trust.
Consumer edits belong to their owners; no consumer cutover is claimed here.
